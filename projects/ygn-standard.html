YGN Standard (Yu-Gi-Oh! Game Notation)

The open, human-readable, deterministic algebraic standard for competitive Yu-Gi-Oh! match logs, game state snapshots (YBN), and AI arbitration—modeled after Chess PGN and FEN.

⚡ Launch Match Notary Web Tool → 🚀 1-Click Dueling Book Userscript npm Package (v1.0.0) GitHub

The Problem: 25 Years of Format Fragmentation

Digital Yu-Gi-Oh! match history has historically suffered from extreme tooling fragmentation:

  • Manual Simulators (Dueling Book): Export raw browser DOM clickstreams (duel_log.txt), where over 91% of lines are pure UI noise (such as "Player viewed deck", "Player signaled OK"). A simple 3-turn duel produces 734 lines and 32KB of redundant text, making automated indexing, tactical analytics, and LLM reasoning impractical.
  • Automated Simulators (YGO Omega, EDOPro): Record matches in closed, binary replay formats (.yrp). These files desynchronize and break whenever card databases update, cannot be diffed in Git, and cannot be consumed by search engines or AI agents.
The Haunted Labs Mission
Just as chess revolutionized game theory and computing by standardizing on PGN (Portable Game Notation) and FEN (Forsyth-Edwards Notation), modern competitive trading card games require an open, formal, algebraic standard.

The Solution: YGN & YBN

Engineered under Haunted Labs, the specification establishes two complementary standards governed by RFC 0001:

  1. YGN (Yu-Gi-Oh! Game Notation): An action-based algebraic grammar capturing normal and special summons, effect activations, target declarations, battle steps, and LIFO chain resolution stacks.
  2. YBN (Yu-Gi-Oh! Board Notation): A snapshot descriptor encoding card identities and zone positions across all 14 field zones, graveyard, banished piles, and hands in a single line.
  3. Deck-Scoped Alias Registry: Maps 8-digit Konami passcodes from standard .ydk files into compact #1..#40 tokens, achieving an 88% to 94% compression ratio over raw simulator logs.

Anatomy of the Algebraic Line
  • Deck-Scoped Aliases: #1..#4 map passcodes from .ydk decklists, compressing repetitive names while retaining deterministic card identity.
  • LIFO Chain Protocol: [C1: Activation // R1: Resolution] encapsulates action and resolution without recording redundant browser UI handshakes.
  • 2-Character Coordinates: ER (Extra Monster Zone Right), M3 (Monster Zone 3), S3 (Spell Zone 3), o.M3 (Opponent Monster Zone 3).
  • YBN Board State: Serializes all 14 field zones, graveyard contents, hand/deck tallies, and active lingering locks into a deterministic string for immediate evaluation by ygo-sim-core.

Multi-Language Ecosystem & Reference Tooling

YGN is maintained as an open community RFC specification with cross-platform reference tooling:

  • Official npm Package (ygn-standard@1.0.0): Reference TypeScript AST parser, lexer, and CLI notary binaries (ygo-notary and ygn-transcribe). Install globally via npm install -g ygn-standard or run instantly via npx ygo-notary.
  • Dueling Book Helper Browser Extension (Tampermonkey Userscript · Manifest V3 WebExtension): 1-click clipboard match export directly inside Dueling Book. Operates post-Cloudflare Turnstile verification inside authenticated browser sessions across both live duels and /replay?id=... rooms.
  • Python Reference Library (ygn): High-performance AST parser, Best-of-3 multi-game demarcation, and negation resolution engine (!NEG(EFF) attribution) designed for competitive data science and machine learning.
  • Lua Emitter (ygn_emitter.lua): Direct integration layer mapping ocgcore bitmasks directly into standardized RFC 0001 zone coordinates and plies with zero C++ simulator overhead.
